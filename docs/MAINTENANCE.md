# 월간 운영·복구 기록

## 매주

- 오류 제보, 404, 빌드 실패, 느린 페이지 확인
- 연락 이메일이 실제로 수신되는지 확인

## 매월

- 세금·법령·건강 기준이 들어간 계산기의 공식 출처와 검토일 확인
- `npm.cmd run check`, `npm.cmd run test:e2e:desktop` 실행
- Search Console의 색인·모바일·페이지 오류 확인

## 분기마다

- 가비아 도메인 갱신일·결제수단 확인
- GitHub·Cloudflare·Google 계정 복구 방법 확인
- 사용하지 않는 접근 권한과 외부 도구 정리

## 규칙 변경 기록 양식

| 날짜 | 계산기 | 이전 버전 | 새 버전 | 변경 이유·공식 출처 | 테스트 | 배포 |
|---|---|---|---|---|---|---|
|  |  |  |  |  |  |  |

## 장애 시 순서

1. 새 배포를 멈춥니다.
2. Cloudflare에서 마지막 성공 배포를 확인합니다.
3. GitHub에서 마지막 정상 변경과 현재 변경을 비교합니다.
4. 원인을 수정한 새 commit을 만들어 테스트합니다.
5. 미리보기 확인 후 main에 반영합니다.
